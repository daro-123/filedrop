# Agent guidance

## Project

Filedrop is a Python 3.10+ desktop utility that shares existing local files through GTK 4 drag-and-drop. Keep the implementation small and follow the existing single-module design.

- `filedrop.py`: path parsing and validation, saved-path storage, drag providers, GTK UI, and CLI entrypoint.
- `tests/test_filedrop.py`: `unittest` behavior tests.
- `README.md`: user-facing behavior, setup, commands, and desktop verification.
- `pyproject.toml`: setuptools packaging and the `filedrop` console entrypoint.
- `install.py`: private virtual environment installation and user-local launcher.
- `mise.toml`: test, build, and install tasks.
- `flake.nix` and `flake.lock`: pinned native development runtime.

## Development commands

Run commands from the repository root.

```sh
# Enter the native GTK development environment when needed.
nix develop

# Run behavior tests.
python3 -m unittest discover -s tests -v
# Equivalent task:
mise run test

# Inspect CLI options without opening a window.
python3 filedrop.py --help

# Launch the UI using an existing file.
python3 filedrop.py --no-decorate --layout grid --height auto test.txt

# Build source and wheel distributions; requires setuptools and wheel.
mise run build
```

GTK requires GTK 4.8+ and PyGObject. Shell mode additionally requires GTK4 Layer Shell and a Wayland compositor supporting layer-shell. Compact mode must not require Layer Shell. Keep GTK imports lazy so CLI parsing and saved-path operations work without a graphical display.

`mise run install` updates the installed app and launcher outside the repository. Run it only when installation is part of the requested task; it is not a verification command.

## Behavior to preserve

- Source files remain unchanged. Drag actions offer COPY only, and each row or tile exports only its own file.
- Reject an entire invalid input batch; do not silently skip invalid files.
- Preserve filename bytes, input order, literal whitespace, and NUL-delimited input support. Do not add shell expansion or URI interpretation.
- Saved queues contain paths, not file data. Preserve ownership checks, private permissions, locking, and atomic replacement.
- Preserve list/grid switching, zoom, keyboard shortcuts, auto-height measurement, and scrolling. Headerless compact windows have equal top and bottom content margins.
- Keep UI styling theme-aware and compatible with supported GTK versions.

## Change and verification rules

- Reuse existing functions and conventions. Avoid new dependencies or abstractions for small fixes.
- Add behavior tests for changed parsing, validation, storage, or CLI contracts. Use temporary directories and isolate environment changes.
- Run the behavior suite after code changes. Native drag-provider tests need PyGObject and GTK typelibs.
- For UI changes, launch the actual window and inspect the affected layout or interaction. Unit tests alone do not verify rendered geometry or desktop drag-and-drop.
- Update `README.md` when user-visible behavior or commands change.
- Do not commit generated bytecode, package output, virtual environments, Nix results, or local assistant backups. Keep `flake.lock` tracked.
